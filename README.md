# Nexus Frontend

Веб-приложение знакомств по общим интересам и смыслу личных историй. React 19, TypeScript, Vite; тёмная сине-фиолетовая палитра, адаптивная навигация и свайпы.

## Пользовательский путь

Главная → регистрация → необязательный выбор тем → основные данные → три коротких вопроса → проверка личного рассказа → подборка.

Вопросы зависят от выбранных тем, включая книги, музыку и психологию. Без конкретных тем используются общие вопросы. Любой вопрос можно пропустить, весь шаг — отложить. Ответы остаются черновиками до явного сохранения. Подробный рассказ скрыт от других участников и используется локальной NLP-моделью для рекомендаций.

В профиле доступны шесть фотографий с взаимным раскрытием, настройки видимости и дополнительные истории. Подборкой можно управлять жестами, кнопками или стрелками клавиатуры. Skip возвращаются по кругу, Like не повторяются. Взаимная симпатия открывает чат.

Основные разделы — «Знакомства», «Чаты», «Профиль», «Для подбора»; уведомления открываются в шапке. «Для подбора» ведёт к закрытым рассказам и повторному интервью. На компьютере подборка помещается в высоту окна, список чатов и история сообщений прокручиваются отдельно. На телефоне переписка открывается отдельным экраном с возвратом к списку. [Основания дизайна](https://github.com/SMART-DATING/nexus-docs/blob/main/design/interface.md).

## Запуск разработки

Рабочий прототип находится в `main`; история реализации — в [PR #5](https://github.com/SMART-DATING/nexus-frontend/pull/5). Новые изменения оформляются отдельными ветками и Pull Request в `main`. Нужны Node.js 22.12+ и запущенный [backend](https://github.com/SMART-DATING/nexus-backend/blob/main/README.md) на 8080.

```sh
git clone --branch main https://github.com/SMART-DATING/nexus-frontend.git
cd nexus-frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Vite проксирует `/api` на `http://127.0.0.1:8080`. Порт фиксирован; занятый 5173 вызывает ошибку вместо перехода на другой порт. Готовность API можно проверить через `GET /api/v1/health`.

## Полный стек

Расположите `nexus-frontend` и `nexus-backend` рядом. Из каталога frontend:

```sh
docker compose up --build --wait
```

Интерфейс доступен на `http://127.0.0.1:8088`. Compose собирает React и Java, запускает PostgreSQL и nginx, ожидает готовности API. На хосте нужен Docker с Linux-контейнерами. `docker compose down` останавливает сервисы, сохраняя БД.

## Голосовой ввод

Используется Web Speech API браузера, если он доступен. Микрофон включается только после отдельного подтверждения; распознанный текст можно изменить. При отсутствии поддержки, отказе в разрешении или ошибке сервиса остаётся текстовый ввод.

Некоторые браузеры передают звук своему сервису распознавания: офлайн-работа и полностью локальная обработка голоса не гарантируются. Nexus не принимает и не хранит аудиозапись. Для доступа к микрофону нужен доверенный контекст: HTTPS или loopback localhost. Поддержка зависит от браузера и устройства; см. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).

## Проверки

```sh
npm test
npm run build
npm run preview
```

Build проверяет TypeScript и создаёт `dist/`; preview обслуживает его на 4173 с тем же API-прокси. На запущенном стеке: `npm run smoke -- http://127.0.0.1:8088` (или 5173 для Vite). Smoke создаёт два тестовых аккаунта и проверяет API через настоящий прокси; используйте отдельную тестовую БД.

Компонентные тесты покрывают регистрацию и вопросы, редактирование черновиков, голосовое согласие и ошибки распознавания, маршруты, свайпы, галерею и HTTP-клиент. CI проверяет сборку и интеграцию с PostgreSQL / nginx и H2 / Vite.

## Структура

| Модуль                                  | Ответственность                                            |
| --------------------------------------- | ---------------------------------------------------------- |
| `App.tsx`, `api.ts`                     | Маршруты, состояние сессии, API                            |
| `Onboarding.tsx`, `GuidedInterview.tsx` | Первое знакомство и вопросы по темам                       |
| `VoiceInput.tsx`                        | Текст, согласие на микрофон, распознавание и fallback      |
| `SwipeDeck.tsx`                         | Карточка, жесты и действия                                 |
| `PhotoUpload.tsx`, `PhotoGallery.tsx`   | Управление своими и просмотр разрешённых фото              |
| `ContextEditor.tsx`                     | Личные истории и повторное интервью                        |
| `ProfileTabs.tsx`                       | Доступные вкладки профиля, сохранение незавершённого ввода |
| `layout.css`, `interview.css`           | Основная компоновка, адаптивность и оформление интервью    |

Сессия хранится в `sessionStorage`, независимо для каждой вкладки. Чат обновляется каждые 2 секунды, события и счётчики сообщений — каждые 7. Счётчик учитывает входящие сообщения; открытый видимый чат подтверждает чтение только уже полученных сообщений. Новые сообщения не перемещают историю вниз, если пользователь читает выше. Сетевые ошибки показываются в интерфейсе, таймаут запроса — 15 секунд. Адрес `/match/{id}` открывает конкретный чат, остальные разделы сохраняются в URL.

## Интерфейс и данные

Карточка на компьютере ограничена шириной 1280 px и доступной высотой окна. Фотография сохраняет пропорции целиком; свободное пространство заполняет мягкая размытая подложка. Фоновый градиент медленно меняется и в подборке использует средний цвет текущего разрешённого фото. Цвет вычисляется в браузере, не сохраняется и никуда не отправляется. Оттенок сохраняется при переходе в другие разделы, чтобы фон не мигал. Свайп перемещает карточку через requestAnimationFrame и transform. Запрос реакции начинается одновременно с переходом; смена анкеты ждёт минимум 360 мс. Ошибка возвращает карточку и разблокирует действия. Первое разрешённое фото следующей анкеты загружается заранее.

Некс — общий анимированный персонаж в регистрации, коротком интервью и разделе «Для подбора». Вопросы выбираются из подготовленного набора по интересам; генеративного диалога нет. Можно сразу написать свободный рассказ, пройти три необязательных вопроса или отложить их. Рассказы сохраняются только по явному действию, существующие доступны в раскрываемом списке. Повтор после сбоя обновления профиля изменяет сохранённую историю вместо создания дубля.

Публичная главная включает переключаемые примеры разговора, интерактивное правило взаимных фотографий, ответы на частые вопросы, навигацию в футере и сопровождающего Некса. Помощь Некса открывается только по кнопке в шапке или футере: пример рассказа, правило фото и личные данные. Нет автоматического появления и перемещений поверх страницы. Карточки книг/музыки открывают соответствующий пример разговора. Демонстрационные ответы не сохраняются. Движение отключается при `prefers-reduced-motion`.

Без сессии `/` открывает информацию о Nexus; `/#login` и `/#register` открывают отдельные формы. Аватар открывает действия аккаунта. Фото можно раскрыть для просмотра с миниатюрами и жестами; серверная квота сохраняется.

В «Мои данные» доступны скрытие анкеты от новых участников и собственная выгрузка JSON. Пауза сохраняет существующие чаты и не удаляет аккаунт. Выгрузка не содержит токенов, хешей паролей и полученных сообщений.

Сборка предназначена для локальных проверок на вымышленных данных. Готовность публичного запуска не заявляется. [Потоки данных, ограничения и задачи выпуска](https://github.com/SMART-DATING/nexus-docs/blob/main/privacy/data-handling.md).

### Фото и смысловая близость

`ProfileCard` используется в подборке и собственном публичном просмотре: фото целиком, управление поверх кадра без уменьшения области фото, имя и город рядом. Описание и все интересы открыты без дополнительной вкладки. Процент сходства личных рассказов виден и на телефоне. Сервер выдаёт наиболее близкий оставшийся уровень с шагом 10%; после его исчерпания переходит ниже, после всех уровней возвращает Skip, сохраняя Like.

`useProfileMedia` обновляет истёкшие ссылки через авторизованный запрос профиля, не заменяя текстовые поля. Автоматическая попытка ограничена для каждого URL, после сбоя есть кнопка повтора. Активные медиа обновляются спустя 12 минут и при возвращении на старую вкладку. Квота, скрытые фото и срок ticket контролируются сервером. В обновлении не используются скрытые URL.

В «Для подбора» короткие темы создают черновик дополнительного рассказа. Сохранение всегда отдельным действием. Основания дизайна: [исследование интерфейса](https://github.com/SMART-DATING/nexus-docs/blob/main/design/interface.md).


### Компактность и спокойные переходы

Внутри анкеты нет отдельной прокрутки или дополнительных карточек с вопросами. Обычная анкета заполняет доступную высоту окна; редкое длинное описание прокручивается вместе со всей страницей. Текст не выделяется при свайпе. Выход продолжается из текущего положения жеста, следующая анкета появляется мягко; отказ сервера возвращает исходную карточку.

Редактор анкеты ограничен 840 px. Публичные темы находятся в отдельном разделе «Для подбора» рядом с личными рассказами, с явным пояснением видимости и отдельным сохранением. Несохранённые поля другой вкладки остаются черновиком. Напоминание дополнить короткий рассказ появляется только в уведомлениях: менее 180 символов суммарного сохранённого текста, не чаще раза в неделю на этом устройстве. Его можно убрать; при достаточном тексте оно исчезает.

Счётчик показывает все оставшиеся подходящие анкеты во всех уровнях, исключая уже оценённые. Некс на главной доступен по запросу и остаётся встроенным в пример разговора. Плавающие карточки вверху ведут к самому примеру выбранной темы; мягкое появление разделов и тёмный футер на всю ширину дополняют главную. Клавиатурный фокус сохранён; на небольших кнопках он обозначен аккуратно.

В коротком окне внутренняя сетка анкеты наследует минимальную высоту рамки: фото не остаётся в её верхней части при увеличении масштаба. Проверены эффективные CSS-размеры для 150%, мобильная верстка и reduced motion. Настоящий browser zoom этой автоматической проверкой не переключается.

### Экранные главы и плавное движение

Высоту разделов главной задаёт содержимое; отступы и заголовки плавно меняются с размером окна. Помощь, карточки и ссылки ведут к началу главы с видимым заголовком. FAQ плавно меняет высоту в обе стороны; закрытый ответ исключается через aria-hidden и inert. Наведение меняет небольшой scale карточки, а плавание — translate, сохраняя фазу и угол. Приватность открывается в окне до 760 px. Кнопки, клавиатура и жест завершают выбор анкеты одной траекторией с наклоном; сбой возвращает карточку. Reduced motion сохраняет мгновенные переходы.


## Экранные разделы и управление чатами

На широком окне каждый раздел главной — законченная композиция высотой с окно: заголовок и крупные карточки заполняют экран, соседний раздел начинается после него. Размеры иллюстраций и карточек зависят от высоты окна, а не от большого пустого отступа. На телефоне и в коротком окне содержание переходит в колонку и растёт по мере необходимости без обрезания. Помощь открывает начало соответствующего раздела.

Порядок основного меню: «Знакомства», «Чаты», «Для подбора», «Профиль». В профиле две вкладки: анкета и фото. «Для подбора» показывает темы и личные рассказы без повторной навигации профиля и кнопки предпросмотра. Черновики сохраняются при переключении этих разделов, пока открыт профиль.

Пустые чаты выровнены по центру. Имя и аватар собеседника открывают свежую публичную анкету; блокировка находится внутри неё. В шапке и анкете видно время последней активности, полученное от сервера. «В сети» означает авторизованный запрос за последние 75 секунд; фоновые опросы не выполняются в скрытой вкладке.

Правая кнопка мыши по чату, Shift+F10 или кнопка «⋯» открывают меню закрепления, отметки прочтения, очистки и удаления. Меню остаётся в пределах окна, поддерживает клавиатуру и телефон. Настройки сохраняются на сервере для текущего аккаунта. Очистка скрывает старую историю только у владельца; удаление скрывает чат из его списка. Новое сообщение возвращает удалённый чат. Переписка другой стороны сохраняется. Список «Заблокированные» снимает собственную блокировку.
