# Nexus Frontend

Русский адаптивный интерфейс сервиса знакомств SMART-DATING: регистрация, профиль, интересы, возрастной фильтр, подбор, взаимные симпатии, чат и уведомления. Данные поступают из работающего API.

## 1. Получить проект
```sh
git clone --branch feature/working-prototype https://github.com/SMART-DATING/nexus-frontend.git
git clone --branch feature/working-prototype https://github.com/SMART-DATING/nexus-backend.git
```
Каталоги должны лежать рядом. Готовая версия — ветка `feature/working-prototype`, PR #5. В main пока заготовка.

## 2. Разработка без Docker
Требуются Node.js 22.12+ и JDK 21. Сначала в каталоге nexus-backend:
```sh
sh scripts/download-model.sh
./mvnw clean package
java -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --nexus.demo=true
```
На Windows вместо `./mvnw` используйте `.\mvnw.cmd`. В отдельном терминале, каталог nexus-frontend:
```sh
npm ci
npm run dev
```
Открыть http://127.0.0.1:5173. Проверка API: http://127.0.0.1:8080/api/v1/health. H2 создаётся автоматически, отдельного сервиса базы для этого режима нет.

## 3. Полный стек Docker / PostgreSQL
Включите Docker Engine/Desktop (Linux containers), перейдите в nexus-frontend:
```sh
docker compose up --build --wait
```
Открыть http://127.0.0.1:8088. Compose собирает этот frontend и соседний ../nexus-backend, запускает PostgreSQL, дожидается готовности API. Устанавливать Java и Node.js на хост для такого запуска не нужно. Подходит для Linux и Windows с Docker.

`docker compose ps` показывает готовность, `docker compose logs backend` — ошибки сервера. `docker compose down` останавливает сервисы и сохраняет БД в named volume; удаление volume очищает данные, поэтому `-v` для обычной остановки не нужен.

## 4. Адреса и прокси
| Режим | Интерфейс | Backend |
|---|---|---|
| npm run dev | 127.0.0.1:5173 | 127.0.0.1:8080 |
| npm run preview | 127.0.0.1:4173 | 127.0.0.1:8080 |
| Docker Compose | 127.0.0.1:8088 | backend:8080 внутри сети |
| Единый JAR с собранным UI | 127.0.0.1:8080 | тот же процесс |

Frontend обращается к `/api/v1`. Vite проксирует `/api` на `http://127.0.0.1:8080` с `changeOrigin:true`. Порт 5173 фиксирован (`strictPort:true`): если занят, запуск сообщит ошибку вместо незаметного перехода на 5174. После изменения vite.config.ts перезапустите Vite. В контейнере используется nginx.conf, а не настройки Vite.

## 5. Проверить основные функции
Войти как demo@nexus.local, пароль `NexusDemo2026!`. Во второй вкладке — demo1@nexus.local, пароль тот же. Демо доступно при запуске backend с nexus.demo=true (в полном Compose уже включено).

1. В профиле задать имя, город, дату рождения (18+) и интересы, сохранить.
2. В знакомствах поставить like второму аккаунту; ответить встречным like из второй вкладки.
3. Открыть «Совпадения», выбрать человека, отправить сообщение.
4. Открыть уведомление, проверить переход к чату.
5. Обновить страницу `/match/{id}`, затем выйти и войти снова.

Сессии вкладок независимы (sessionStorage). Сообщения обновляются каждые 2 секунды, совпадения/уведомления — каждые 7. Чат принимает ответы 201, выход — пустой 204; ошибки API и прокси показываются пользователю. Сетевой запрос ограничен 15 секундами.

## 6. Сборка и проверки
```sh
npm test
npm run build
npm run preview
```
Build включает проверку TypeScript и создаёт dist. После запуска API и интерфейса выполните:
```sh
npm run smoke -- http://127.0.0.1:5173
```
Для Docker передайте http://127.0.0.1:8088. Smoke создаёт два тестовых аккаунта с уникальными адресами и проверяет профиль, интересы, предпочтения, подбор, match, сообщение, уведомление и выход через настоящий HTTP-прокси. Эти аккаунты остаются в тестовой базе.

## 7. Структура
`src/App.tsx` — экраны и состояние, `src/api.ts` — HTTP-клиент и типы, `src/style.css` — оформление; `src/*.test.*` — компонентные проверки; `scripts/smoke.mjs` — интеграционный HTTP-сценарий. Dockerfile собирает dist, nginx.conf обслуживает SPA и `/api`.

## 8. Если запросы не проходят
- Сначала открыть `/api/v1/health` напрямую на 8080 и через 5173. Если прямой запрос не работает, смотрите лог backend.
- 401 означает истекшую/отозванную сессию — войдите заново.
- 400 означает неверные поля, 403 — чужой чат, 409 — уже сохранённую реакцию или незаполненный профиль.
- 502/сообщение о недоступном сервере — backend не запущен или у прокси неверный адрес.
- Vite сообщает занятый порт — остановите старый frontend; два экземпляра на 5173 одновременно не нужны.
- Карточек нет — заполните профиль, расширьте возраст и учтите, что Like/Skip сохраняются.

Демоанкеты используют 14 локальных иллюстрированных SVG-аватаров; пользователь может загрузить собственное фото в «Мой профиль» (JPEG/PNG до 5 МБ), заменить или удалить его. До загрузки показываются инициалы. Подбор работает по пересечению интересов, сообщения обновляются опросом вместо WebSocket. Процент на карточке — доля общих интересов.

Тёмная сине-фиолетовая палитра дополняется анимациями карточек и взаимной симпатии; настройка reduced motion отключает движение. Подсказки первого сообщения только заполняют поле. Разделы `/`, `/#matches`, `/#profile`, `/#notifications` и чат `/match/{id}` сохраняются при обновлении; история браузера синхронизирована с экраном. Карточки поддерживают свайп мышью/пальцем, кнопки Skip/Like и стрелки клавиатуры при фокусе на карточке. Кликабельные интересы показывают идеи для знакомства, превью следующих анкет меняют текущую карточку. POST /recommendations/next автоматически возвращает собственные Skip только после окончания непросмотренных подходящих анкет; Like и чаты сохраняются. Если все подходящие анкеты лайкнуты, предлагается изменить фильтр или обновить подборку.

## Смысловой подбор и шесть фото

До 12 личных рассказов (20–6000 символов) для локальной модели RuBERT-tiny2, 312-мерные векторы и cosine. Тексты и названия видит только автор через /contexts/me. Публичные темы необязательны и не определяют ranking. Для подбора нужен хотя бы один рассказ. Фото 0–6: свои доступны полностью, чужие — в пределах числа своих. На сервере проверяются квота, порядок и временная ссылка. Галерея поддерживает добавление, замену, удаление и перестановку. Старый аватар переносится без потери аккаунтов/чатов.

Перед первой локальной сборкой скачайте модель скриптом backend/scripts/download-model.ps1 (PowerShell) или download-model.sh (Linux); Docker делает это сам. Путь можно задать NEXUS_MODEL_DIR. Подробности модели и ограничений — MODEL.md в backend и architecture/MODEL.md в docs.
